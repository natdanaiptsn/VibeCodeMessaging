# ทดสอบอัตโนมัติด้วย Playwright (E2E)

Playwright เปิดเบราว์เซอร์จริง (Chrome) แล้วคลิกและพิมพ์แทนเรา จากนั้นตรวจว่าหน้าเว็บแสดงผลถูกต้อง
ชุดเทสต์นี้รันกับ **เว็บจริง** (`https://vibe-code-messaging.vercel.app`) ได้อย่างปลอดภัย และตั้งชื่อเทสต์ตามรหัสในไฟล์ Excel Test Case

## เทสต์อะไรบ้าง

| ไฟล์ | Test case ใน Excel |
|---|---|
| `projects.spec.ts` | B1 สร้างโปรเจกต์, B2 เปลี่ยนชื่อ, B3 ข้อมูลแยกโปรเจกต์, B4 ตัวกรอง, B10 ลบโปรเจกต์ |
| `members.spec.ts` | B5 คนนอกเปิดไม่ได้, B6 เพิ่มสมาชิก (ชื่อผู้ใช้ / อีเมล), B7 สิทธิ์เจ้าหน้าที่, B8 สิทธิ์ผู้ดูแล, B9 นำออก / ออกเอง |
| `auto-reply.spec.ts` | D2 Exact/Contains, D3 หลายข้อความ + สลับลำดับ, D4 สูงสุด 5 ข้อความ, D5 จำกัดต่อการตอบ, D6 Priority, D7 ปิดกฎ, D8 Default Reply, D9 ตัวแปร, D12 Postback, D13 Regex/ReDoS, D14 ปิด Auto Reply |
| `test-chat.spec.ts` | E1 แชททดสอบ (รวม D1 TestFlex), E2 จำลองรูป/สติกเกอร์/ตำแหน่ง/เพิ่มเพื่อน (แทน D10, D11), E3 ไม่ตรงกฎ |
| `templates.spec.ts` | F1 Text Message + ตัวแปร, F2 Flex Builder, F3 นำเข้า JSON ผิด, F4 ลบเทมเพลตที่ใช้อยู่ไม่ได้ |
| `misc.spec.ts` | H2 Webhook ไม่มีลายเซ็น, H3 โหมดมืด, H4 มือถือ |

**ยังต้องทดสอบด้วยมือ:**
- หมวด A (บัญชี / Google / LINE Login): เว็บของ Google และ LINE บล็อกบอท
- หมวด C (เชื่อม LINE OA)
- หมวด G (ลูกค้าจริงและโควตาข้อความ)
- ส่วนที่ต้องดูผลในมือถือของ D1, D10, D11
- Cooldown ของ D8
- H1 และ H5

### ทำไมรันกับเว็บจริงได้อย่างปลอดภัย
- ใช้ **บัญชีทดสอบแยก 2 บัญชี** ระบบให้แต่ละบัญชีเห็นเฉพาะโปรเจกต์ของตัวเอง ถ้าเทสต์ผิดพลาดก็แตะโปรเจกต์จริงไม่ได้ และถ้าใส่บัญชีผู้ดูแลหลัก เทสต์จะไม่ยอมรัน
- ทุกเทสต์ **สร้างโปรเจกต์ใหม่ชื่อ `[E2E] ...` แล้วลบทิ้งเมื่อจบ** แม้เทสต์จะไม่ผ่านก็ตาม หลังรันจบยังมีขั้นตอนเก็บกวาดโปรเจกต์ `[E2E]` ที่ค้างอยู่อีกรอบ
- ไม่เชื่อม LINE OA และทดสอบกฎผ่าน **แชททดสอบ** ซึ่งไม่ส่งข้อความจริง ไม่บันทึกข้อมูล และไม่เสียโควตา
- รันทีละเทสต์ และล็อกอินครั้งเดียวแล้วใช้ cookie ซ้ำ จึงไม่โดนล็อกบัญชี

## ขั้นตอนที่ 1: ติดตั้ง (ทำครั้งแรกครั้งเดียว)

1. ติดตั้ง **Node.js** เวอร์ชัน 20 ขึ้นไปจาก https://nodejs.org (เลือก LTS) แล้วเช็คด้วยคำสั่ง
   ```bash
   node -v
   ```
2. ติดตั้ง **Git** จาก https://git-scm.com แล้วดาวน์โหลดโปรเจกต์
   ```bash
   git clone https://github.com/natdanaiptsn/VibeCodeMessaging.git
   ```
   ```bash
   cd VibeCodeMessaging
   ```
3. ติดตั้งแพ็กเกจทั้งหมด รวมถึง Playwright ที่ระบุไว้ใน `package.json` แล้ว
   ```bash
   npm install
   ```
4. ดาวน์โหลดเบราว์เซอร์ Chromium ให้ Playwright ใช้ (ประมาณ 150 MB)
   ```bash
   npx playwright install chromium
   ```
   ถ้าใช้ Linux ให้เติม `--with-deps` เพื่อติดตั้งไลบรารีที่เบราว์เซอร์ต้องใช้ด้วย

> โปรเจกต์ใหม่ที่ยังไม่มี Playwright จะเริ่มด้วย `npm init playwright@latest` ซึ่งสร้าง `playwright.config.ts` และโฟลเดอร์ตัวอย่างให้ แต่โปรเจกต์นี้ตั้งค่าไว้แล้ว จึงข้ามขั้นนี้ได้

## ขั้นตอนที่ 2: สร้างบัญชีทดสอบ 2 บัญชีบนเว็บจริง

1. เข้าเว็บด้วยบัญชีผู้ดูแลหลัก แล้วไปที่เมนู **บัญชีและผู้ใช้งาน** → แท็บ **ผู้ใช้งาน** → กด **เพิ่มผู้ใช้**
2. สร้างบัญชีที่ 1 เช่น ชื่อผู้ใช้ `e2e.owner` สิทธิ์ **เจ้าหน้าที่** และตั้งรหัสผ่าน
3. สร้างบัญชีที่ 2 เช่น `e2e.member` สิทธิ์ **เจ้าหน้าที่** ถ้าใส่อีเมลด้วย จะได้ทดสอบการเพิ่มสมาชิกด้วยอีเมล (B6) เพิ่มอีกข้อ

ห้ามใช้บัญชีผู้ดูแลหลักและห้ามตั้งสิทธิ์เป็น "เจ้าของ" เพราะเทสต์จะไม่ยอมรัน

## ขั้นตอนที่ 3: ใส่ชื่อผู้ใช้และรหัสผ่านในไฟล์ `.env.e2e`

คัดลอกไฟล์ตัวอย่าง (บน Windows ใช้ `copy` แทน `cp`)
```bash
cp .env.e2e.example .env.e2e
```
แล้วแก้ไฟล์ `.env.e2e`
```
E2E_BASE_URL=https://vibe-code-messaging.vercel.app
E2E_OWNER_USERNAME=e2e.owner
E2E_OWNER_PASSWORD=รหัสผ่านบัญชีที่ 1
E2E_MEMBER_USERNAME=e2e.member
E2E_MEMBER_PASSWORD=รหัสผ่านบัญชีที่ 2
```
ไฟล์ `.env.e2e` จะไม่ถูก commit ขึ้น GitHub (อยู่ใน `.gitignore`) ส่วน cookie หลังล็อกอินจะถูกเก็บที่ `e2e/.auth/` ซึ่งก็ไม่ถูก commit เช่นกัน

## ขั้นตอนที่ 4: รันเทสต์

รันทั้งหมด (ใช้เวลาประมาณ 2 นาที):
```bash
npm run e2e
```

เปิดหน้าจอ UI ของ Playwright ที่ดูเทสต์ทำงานทีละขั้นได้ (แนะนำตอนเริ่มต้น):
```bash
npm run e2e:ui
```

รันเฉพาะไฟล์เดียว:
```bash
npx playwright test e2e/members.spec.ts
```

รันเฉพาะข้อ เช่นทุกข้อที่ชื่อมี B6:
```bash
npx playwright test -g "B6"
```

เปิดเบราว์เซอร์ให้เห็นระหว่างรัน:
```bash
npx playwright test --headed
```

ผลที่ควรได้ เมื่อผ่านทุกข้อจะขึ้นประมาณนี้
```
  ✓  [setup] › เข้าสู่ระบบ: บัญชีทดสอบหลัก ...
  ✓  [chromium] › e2e/auto-reply.spec.ts › D2 Exact Match กับ Contains
  ...
  36 passed (1.8m)
```

## ขั้นตอนที่ 5: ดูผลเมื่อมีข้อที่ไม่ผ่าน

เปิดรายงาน ซึ่งมีภาพหน้าจอ วิดีโอ และ trace ของข้อที่ไม่ผ่าน:
```bash
npm run e2e:report
```

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| `ล็อกอิน ... ไม่สำเร็จ` | ชื่อผู้ใช้หรือรหัสผ่านใน `.env.e2e` ผิด หรือบัญชีถูกล็อกเพราะใส่ผิดหลายครั้ง (รอ 15 นาที) |
| `ต้องเป็นบัญชีทดสอบแยก` | ใส่บัญชีผู้ดูแลหลัก หรือบัญชีที่มีสิทธิ์ "เจ้าของ" ให้เปลี่ยนเป็นบัญชีทดสอบ |
| บางช่วงรอนานเกือบ 1 นาที | ปกติ ระบบจำกัดการสร้างโปรเจกต์ 20 ครั้งต่อนาที เทสต์จะรอแล้วลองใหม่ให้เอง |
| หาปุ่มหรือข้อความไม่เจอ | ข้อความบนหน้าเว็บอาจถูกแก้ หรือเว็บจริงยัง deploy โค้ดล่าสุดไม่เสร็จ ให้ดูภาพหน้าจอในรายงาน |
| ล็อกอินบ่อยเกินไป | cookie ใช้ได้ 7 วัน ถ้าอยากล็อกอินใหม่ ให้ลบโฟลเดอร์ `e2e/.auth` |

ถ้ากดหยุดกลางคัน อาจมีโปรเจกต์ `[E2E] ...` ค้างอยู่ในบัญชีทดสอบ ซึ่งจะถูกลบให้ตอนรันรอบถัดไป

## โครงสร้างไฟล์

```
playwright.config.ts      ตั้งค่า (เว็บที่ทดสอบ, รันทีละเทสต์, เก็บภาพ/วิดีโอเมื่อไม่ผ่าน)
e2e/
  auth.setup.ts           ล็อกอินบัญชีทดสอบทั้งสองบัญชี (ครั้งเดียว แล้วใช้ cookie ซ้ำ)
  cleanup.teardown.ts     เก็บกวาดโปรเจกต์ [E2E] ที่ค้างอยู่หลังรันจบ
  *.spec.ts               เทสต์ แยกตามหมวดใน Excel
  support/
    env.ts                อ่านค่าจาก .env.e2e
    fixtures.ts           ของที่เทสต์ใช้ได้ทันที: project, chat, api, memberPage, memberApi
    api.ts                ตัวช่วยเรียก API เพื่อเตรียมข้อมูล (สร้างกฎ / เทมเพลต / ตั้งค่า)
    test-chat.ts          ตัวช่วยใช้แชททดสอบ (ส่งข้อความ แล้วตรวจคำตอบ)
```

## เขียนเทสต์เพิ่มเอง

ตัวอย่าง: สร้างกฎผ่าน API แล้วตรวจคำตอบในแชททดสอบ
```ts
import { test, expect } from "./support/fixtures";

test("D2 ตัวอย่าง: พิมพ์ราคาแล้วได้คำตอบ", async ({ page, project, chat }) => {
  // project = โปรเจกต์ [E2E] ใหม่ที่ถูกลบให้อัตโนมัติหลังจบ
  await project.api.createRule({
    matchType: "EXACT",
    keywords: ["ราคา"],
    messages: [{ type: "TEXT", text: "ราคา 100 บาท" }],
  });
  await page.goto(`/p/${project.id}/customers`);
  await chat.expectReply("ราคา", { contains: ["ราคา 100 บาท"] });
});
```

ให้ Playwright อัดการคลิกเป็นโค้ดให้ โดยเปิดเว็บในสถานะที่ล็อกอินบัญชีทดสอบอยู่แล้ว:
```bash
npx playwright codegen --load-storage=e2e/.auth/owner.json https://vibe-code-messaging.vercel.app/projects
```

เคล็ดลับ:
- หาปุ่มและช่องกรอกด้วย `getByRole`, `getByLabel` หรือ `getByText` (ใช้ข้อความภาษาไทยได้) จะทนกว่าการอ้าง class ของ CSS
- ถ้าชื่อสั้น ๆ ไปตรงกับปุ่มอื่นด้วย ให้ใส่ `exact: true` เช่น ปุ่ม "ส่ง" กับ "ส่งรูปภาพ (จำลอง)"
- ข้อมูลที่สร้างเองให้ใช้ `uniqueName()` จะได้ชื่อที่ขึ้นต้นด้วย `[E2E]` และไม่ซ้ำกัน
- เว็บจริงจำกฎและการตั้งค่าไว้ 5 วินาที หลังแก้กฎให้ตรวจผลด้วย `chat.expectReply()` ซึ่งจะลองซ้ำให้เอง

## ทดสอบกับเครื่องตัวเองแทนเว็บจริง

เปิดระบบในเครื่องด้วย `npm run dev` (ต้องมีฐานข้อมูลตามที่เขียนไว้ใน README หลัก) แล้วสร้างบัญชีทดสอบ 2 บัญชีในระบบนั้น
จากนั้นแก้ `.env.e2e` เป็น
```
E2E_BASE_URL=http://localhost:3000
```
